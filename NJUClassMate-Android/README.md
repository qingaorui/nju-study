# 南哪儿课表 · Android / APK 版

南京大学课表助手，Android 原生（Kotlin + WebView UI）。

**这一版是为 HarmonyOS 4 及更早的机型做的**：那些系统是安卓内核、只认 APK，
装不了鸿蒙的 HAP。相对鸿蒙版有一个明显优势——**能真正装到你手机上**，
因为 Android 允许自签名安装，不需要任何开发者账号。

---

## 一、先说清楚能做到什么、做不到什么

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 内置浏览器打开南大课表并读取 | ✅ | 四个入口，四个抓取脚本，和鸿蒙版**同一套代码** |
| **手动录入课程** | ✅ | 补录教务系统里没有的课（实验、组会、旁听），可增可删 |
| 桌面小组件（下一节课 / 今日课表） | ✅ | 2×2 到 4×4 自适应 |
| **锁屏上显示下一节课** | ✅ | **用常驻通知实现**，带自走秒倒计时。见第三节 |
| 上课提醒 | ✅ | AlarmManager 精确闹钟，应用没打开也准时弹 |
| **「现在是第几周」自动设置** | ✅ | 设第 N 周自动反推开学日期，不用翻日历 |
| 开机自启 + 自动刷新 | ✅ | **Android 官方就支持**，不像鸿蒙那样受限 |
| 考试倒计时、导出 .ics、作息校准 | ✅ | 全部保留 |
| ~~锁屏小组件~~ | ❌ | Android 从 5.0 起删掉了这个能力，没有公开 API。**但锁屏显示本身已经用通知实现了**，所以这个缺失不影响需求 |

"锁屏上看到下一节课"这个需求**是做到的**，只是实现手段不是小组件而是常驻通知——
原因和取舍在第三节展开。

**装完之后第一件事请去「设置 → 本机适配」走一遍**（第四节）。
国产 ROM 默认会压制后台，课前提醒和锁屏通知缺了授权会**静默失效**，
不报错、也没日志——这是整个工程最容易被误判成"功能是坏的"的地方。

## 二、架构：一份逻辑，两种皮肤

```
┌─────────────────────────────────────────────────┐
│  MainActivity (WebView)                         │
│    assets/www/index.html + style.css + app.js   │
│    ↑ 只负责画，不负责算                            │
└───────────────────┬─────────────────────────────┘
                    │  window.NJU.call(method, args)  ← 唯一的桥
┌───────────────────┴─────────────────────────────┐
│  Kotlin                                          │
│    core/Engine.kt        ★ 「下一节课」唯一实现      │
│    core/LockScreenContent.kt  ★ 锁屏内容生成（纯函数）│
│    core/DeviceAdapt.kt   ★ 本机适配规则（纯函数）    │
│    core/Store.kt            SharedPreferences    │
│    core/Models.kt           数据模型               │
│    web/WebBridge.kt         JS ↔ 原生（唯一入口）   │
│    device/DeviceCompat.kt   读系统状态 / 跳系统设置  │
│    widget/*                 桌面小组件              │
│    notify/*              ★ 锁屏常驻通知             │
│    reminder/*               AlarmManager 提醒      │
│    work/RefreshWorker.kt    WorkManager 兜底       │
│    boot/BootReceiver.kt     开机自启               │
│    export/IcsExporter.kt    导出日历               │
└─────────────────────────────────────────────────┘
```

**关键决定：算法只在 Kotlin 里实现一份。**
网页通过 `NJU.call('state')` 拿到算好的结果来渲染，自己不重算。
桌面小组件、锁屏通知、网页三处都调同一个 `Engine`。好处有两个：
1. 不会出现"网页算出 09:00、小组件算出 09:50"这种灵异 bug；
2. `Engine`、`LockScreenContent`、`DeviceAdapt` 三个都是**纯函数、不依赖任何 Android API**，
   所以能跑 **JVM 单元测试**——这一点比 HarmonyOS 版强太多，
   那边 ArkTS 完全没法在电脑上编译验证。
   凡是"决策"（下一节是哪节、锁屏显示什么、该提示哪些授权）都放这一层；
   凡是"胶水"（读系统状态、发通知、跳设置页）放平台层。

**桥只有一个入口。** `window.NJU.call(method, args)` 是网页和原生之间**唯一**的通道，
方法名是字符串，所以编译器帮不上忙——`tools/check_bridge.py` 会交叉校验
"网页调用的方法 ↔ Kotlin 分发表"，防止出现"函数写好了但忘了接进 when"这种
点了没反应的静默故障。

**抓取脚本一行没改，直接从鸿蒙工程复制。**
因为 JS 接口名两边都叫 `njuBridge`，`window.njuBridge.postMessage(json)` 这个约定完全通用。
四份脚本、94 项离线断言，两边共享。`tools/run_tests.sh` 会检查两个工程的副本是否逐字节一致。

## 三、锁屏显示：为什么用通知，以及它怎么保持正确

### 为什么不是小组件

Android 从 5.0（2014）起就移除了锁屏小组件（Keyguard widget）能力，三方应用
拿不到任何替代 API。**常驻通知是唯一能躺在锁屏上的东西**——只要在通知上带
`setVisibility(VISIBILITY_PUBLIC)`，内容就会原样出现在锁屏上，不解锁也能看到。

这不需要任何系统权限，也不需要前台服务（所以不额外耗电、不会被系统杀）。
通知由系统的 NotificationManagerService 持有，**应用进程被杀了通知也不会消失**。

### 三个关键设计

**1. 自走秒倒计时。** 锁屏上那行"还剩 32 分钟"用的是 `Chronometer` 的
countDown 模式，由**系统自己刷新**，不是我们在后台每秒重发通知。

这一点很重要：为了跳秒而反复重发通知会唤醒进程、耗电，还会被系统限流
（Android 对同一应用的通知频率有节流）。所以状态**只在真正翻转时才重发**：

| 触发点 | 什么时候 |
| --- | --- |
| 整点闹钟 | 每节课的上课/下课时刻（`ReminderScheduler` 的 `TYPE_REFRESH` 早就排好了） |
| 开机自启 | 重启后 `BootReceiver` |
| 息屏 | `ACTION_SCREEN_OFF` 动态注册，用户即将看锁屏的那一瞬间 |
| 数据变更 | 重新导入、改设置、改作息 |
| 打开应用 | `MainActivity.onResume` |
| 手动点通知上的「刷新」 | 走广播，不用打开 App |
| 兜底 | WorkManager 15 分钟一次 |

两次重发之间，倒计时由 Chronometer 自己走，所以**任何时刻看都是准的**。
`Chronometer` 走的是 `elapsedRealtime`（含深睡眠），所以息屏几小时后回来时间仍然对。

**2. 不伪造重要性。** 渠道用 `IMPORTANCE_DEFAULT` + 静音（关声音、关振动）。
不用 `IMPORTANCE_LOW` 是有代价的：国产 ROM（EMUI / 鸿蒙）普遍把 LOW
折叠进"不重要通知"，锁屏上直接看不见——那就白做了。

**3. 状态只有一份。** 通知和桌面小组件共用 `Engine.resolve()`，
「看明天」按钮也共用同一个 `todayCardForceTomorrow` 开关。
两个视图说两套话（通知说看明天、卡片还停在今天）比两个都不刷新更糟。

### 数据流

```
                    ┌── 整点闹钟 / 开机 / 息屏 / 打开应用 / 手动刷新
                    ↓
        WidgetUpdater.updateAll(ctx)          ← 界面刷新的统一入口
                    │
        ┌───────────┼────────────┐
        ↓           ↓            ↓
  下一节课小组件  今日小组件   NextClassNotifier
                                    │
                        buildLockScreenContent()   ← 纯函数，可单测
                                    │
                    收起态布局 / 展开态布局（RemoteViews）
                                    │
                              锁屏上的那条通知
```

`buildLockScreenContent()` 刻意写成不碰任何 Android API 的纯函数，
所以"锁屏上到底显示什么"这个决策能在 JVM 上跑断言——上课中 / 课前 /
今天没了 / 明天才有 / 假期 / 没导入，六个分支都有覆盖（见第八节）。

### 用户看不见它的时候，怎么排查

常驻通知不见了，原因几乎都不在 App 里，而是这两种：

1. **通知权限没给**（Android 13+ 要运行时授权）——设置页会直接标红提示；
2. **系统里「锁屏通知」被设成了隐藏**——这个 App 读不到，
   设置页只能提示你去系统设置里确认。

所以设置页的「锁屏显示」分组里有一行状态检测，会明确告诉你卡在哪一步，
而不是让你对着一个空锁屏猜。

### 关于通知被划走

`setOngoing(true)` 之后在原生 Android 上是划不走的。但部分厂商 ROM
（包括 EMUI）允许划走非前台服务的常驻通知。真被划走也不用管：
下一次整点闹钟或 15 分钟的兜底任务会把它重新发出来。

## 四、本机适配：哪些系统授权必须补上

这个 App 的三个核心承诺——**课前提醒、锁屏通知、小组件保持最新**——
全都依赖后台任务。而国产 ROM（尤其华为 EMUI / 鸿蒙）对三方应用的后台管控
比原生 Android 严得多，**这四项默认都是被压制的**：

| 需要补的授权 | 不补会怎样 | 能自动检测吗 |
| --- | --- | --- |
| 精确闹钟（Android 12+） | 只能用非精确闹钟，息屏久了提醒偏几分钟 | 能 |
| 忽略电池优化 | EMUI 会冻结应用：闹钟不响、数据停在旧的 | 能 |
| 应用启动管理（华为/荣耀特有） | 重启后闹钟表不重建、通知不会自己回来 | **不能**，系统没有公开接口 |
| 通知 / 锁屏通知 | 锁屏上看不到下一节课 | 部分能 |

**关键在于：这四项缺了都不会报错**，只表现为"提醒没响""显示的课表是昨天的"。
用户根本无从判断是功能坏了、还是没配好。

所以设置页的第一组就是「本机适配」：显示当前机型、逐项给状态、
点一下直接跳到对应的系统设置页。这张表不是写死的通用清单，
而是**按机型算出来的**：

- **精确闹钟**只在 Android 12+ 才出现——低版本压根没这道门，显示它纯属噪音
- **「应用启动管理」**只在华为/荣耀机型出现——别的系统没这个页面，
  给一个跳不过去的按钮比不提示更糟
- **电池优化**在华为上是红色警告、在原生 Android 上只是灰色提示——
  前者会真的把应用冻掉，后者只是延迟几分钟

"该显示哪几项、哪项算不合格"写在 `core/DeviceAdapt.kt` 里，是**纯函数**，
所以能在 JVM 上跑断言（见第八节）；跳转这些碰系统 API 的部分在
`device/DeviceCompat.kt`。

### 跳转为什么要写一串候选

这些页面全是 OEM 私有的，没有任何稳定契约：华为「应用启动管理」的类名
在 EMUI 各版本之间改过至少三次，荣耀独立后又换了包名，
部分 ROM 还把 Activity 设成不导出（`resolveActivity` 成功、`startActivity` 照样抛异常）。
所以每个跳转都是"一串候选 + 逐个试探 + 失败就如实告诉用户自己去设置里找"，
而不是崩掉或者假装成功。

### 关于 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`

Google Play 对这条权限有上架限制（要求说明用途），但本应用是**自签名侧载分发、
不上 Play**，所以没有这个约束。是否加入白名单完全由用户点那一下决定，
应用不会自己申请、也不会绕过。关掉它 App 照样能用，只是提醒可能不准时。

### 你手上这台机器：华为 Mate 40 Pro（NOH-AN00）

已通过 USB 枚举确认（`VID_12D1&PID_107E` 的 `MI_00` 接口报出机型 `NOH-AN00`）。
它是**华为系 + Android 12（API 31）基线**，所以上面四项**全都会出现在适配面板里**：

| 项 | 为什么这台机器会命中 | 手动路径（跳转失败时用） |
| --- | --- | --- |
| 精确闹钟 | 鸿蒙 4 = Android 12，正好是这道门生效的版本 | `设置 → 应用和服务 → 应用管理 → 南哪儿课表 → 权限 → 闹钟和提醒` |
| 忽略电池优化 | 华为系，不关会冻结后台 | 面板那一行会直接弹确认框；找不到就走 `设置 → 电池 → 更多电池设置` |
| 应用启动管理 | 华为/荣耀特有 | `设置 → 应用和服务 → 应用启动管理 → 南哪儿课表` → **关掉「自动管理」**，再把「允许自启动」「允许关联启动」「允许后台活动」三个都打开 |
| 通知 / 锁屏通知 | — | `设置 → 通知和状态栏 → 南哪儿课表` → 允许通知；再进 `锁屏通知` 选「显示」 |

⚠️ **「应用启动管理」和「电池优化」是两套不同的机制，都要开。**
只关了电池优化、没开启动管理的话，重启手机后闹钟表不会重建，表现就是
"开机之后提醒就不响了"。

**另外：要给这台手机装 App，需要先打开 USB 调试。** 目前它只挂在 MTP 模式
（枚举里只有文件传输接口，没有调试接口），所以电脑这边推不进去：

1. `设置 → 关于本机` → 连续点「版本号」7 次，开启开发者模式
2. `设置 → 系统和更新 → 开发人员选项` → 打开 **USB 调试**
3. 重新插拔数据线，手机上弹出「是否允许 USB 调试」→ **允许**
4. 电脑上再跑 `adb devices`，应该能看到设备

不开 USB 调试也没关系——把 APK 拷进手机、用文件管理器点开就能装。

## 五、小组件是怎么保持更新的

RemoteViews 不会自己跳秒，倒计时文字会变旧。Android 这边用了四层：

| 层次 | 机制 | 作用 |
| --- | --- | --- |
| **精确** | `AlarmManager.setExactAndAllowWhileIdle` | 在每节课**上课时刻**和**下课时刻**各触发一次，翻状态最准 |
| **兜底** | `WorkManager` 15 分钟周期任务 | 覆盖跨周、权限被撤、重启后闹钟丢失等情况 |
| **系统** | `updatePeriodMillis = 30 分钟` | 系统给的最小周期，保底 |
| **事件** | `onAppWidgetOptionsChanged` / 数据变更 | 用户改尺寸、改设置时立刻重排 |

Android 12+ 精确闹钟要在系统设置里授权，未授权时代码会自动降级成
`setAndAllowWhileIdle`（可能偏几分钟，但不会不响）。

**开机自启**是 Android 官方能力：`BootReceiver` 监听 `BOOT_COMPLETED`，
重启后重建小组件数据和闹钟表（AlarmManager 的闹钟重启后会全部丢失）。
`MY_PACKAGE_REPLACED` 也一起处理——覆盖安装后闹钟同样会丢。

## 六、安全边界

- **`addJavascriptInterface` 把桥暴露给 WebView 加载的任何页面**，
  所以主界面的 WebView 只加载本地 assets，`shouldOverrideUrlLoading` 把所有外链
  丢给系统浏览器，绝不在带桥的 WebView 里打开。
- **导入用的 WebView 是另一个 Activity**，它的桥只做一件事：
  接收抓取结果。它不暴露任何读写接口，加载的也都是 nju.edu.cn。
- **账号密码全程不经过应用**：登录发生在官方页面，应用只在页面渲染完后读一次 DOM。
- **明文 HTTP 只对南大域名放开**（见 `network_security_config.xml`）。
  因为 `xk.nju.edu.cn` / `yjsxk.nju.edu.cn` 确实还在用 http，
  一刀切禁止会让这两个入口直接打不开；其余域名一律强制 HTTPS。

## 七、构建

环境由脚本装到 `D:\android-dev`（C 盘当时只剩 47G，D 盘 148G）：

```bash
python tools/setup_android_env.py     # 一次性：JDK + Android SDK + Gradle
bash tools/build_apk.sh               # 跑单测 + 出 APK
```

`build_apk.sh` 会自动：定位工具链 → 跑 JVM 单测 → 构建 → 把 APK 收进 `dist/`
→ 打印大小和 SHA256。常用参数：

```bash
bash tools/build_apk.sh --test-only   # 只跑引擎单测
bash tools/build_apk.sh --release     # release 包（脚本自动用 keytool 自签，不需要任何账号）
bash tools/build_apk.sh --clean       # 先清理
```

> **网络环境的一个坑**：这台机器上 `github.com` 是不可达的。
> Adoptium 的 JDK 和 Gradle 官方发行版都会 302 到 github.com，直接下载失败（502）。
> 所以 `setup_android_env.py` 刻意换了两个非 GitHub 的源：
> JDK 用 Amazon Corretto（AWS CDN），Gradle 用腾讯云镜像。
> Android SDK 本身在 dl.google.com，不受影响。

## 八、装到手机上

```bash
adb install -r dist/nju-classmate-release-*.apk
```

**或者更简单**：把 APK 拷进手机，用文件管理器点开安装。
系统会提示「允许来自此来源的应用」，同意即可——这就是安卓，不需要账号、不需要电脑。

> `dist/` 里**只有 release 一个包**，这是刻意的：两个不同签名的包
> （比如 release + debug）如果混着装，第二个会因签名不一致而装不上，
> 必须先卸载——对用户来说是"莫名其妙装不了"。要 debug 包就单独构建一次，
> 别让两个包同时躺在 dist 里。

首次使用（**第 1 步别跳过**，它决定了后面几项功能到底能不能用）：

1. **打开 App →「设置 → 本机适配」**：这是针对你这台手机的 ROM 该补的授权。
   逐项点进去打开——精确闹钟、忽略电池优化、（华为机型）应用启动管理、通知。
   全绿了就往下走；有红项没处理的话，课前提醒和锁屏通知会静默失效
2. 「一键导入课表」→ 选入口 → 登录（连不上就先连南大 VPN）
3. 停在「我的课表」页面，等它自动读取（失败会重试 4 次，也可手点「手动读取当前页」）
4. 「设置 → 学期 → 现在是第几周」，点 + 把本周设成实际的周数（自动反推开学日期）
5. 到「设置 → 作息时间表」对着自己的课表核对一次时间
6. **长按桌面空白处 → 小组件 → 南哪儿课表** → 添加「下一节课」「今日课表」
   （两个小组件在列表里各自有名字和说明，不会分不清）
7. 锁屏显示默认是开着的。第一次装完先**息屏看一眼**确认能看到；
   如果看不到，去「设置 → 锁屏显示 → 立即推送一次」，那行状态会告诉你卡在哪一步

**如果课前提醒没响 / 数据是旧的**，去「本机适配」看——那四项缺了都不会报错，
只会表现为"功能是坏的"。这是本工程最容易被误判成 bug 的地方。

**如果锁屏上看不到**，按顺序检查（都是系统侧的问题，不是 App 的）：

1. `设置 → 通知和状态栏 → 南哪儿课表` → 允许通知（Android 13+ 首次打开会弹权限框）
2. `设置 → 通知和状态栏 → 锁屏通知` → 不要设成「不显示」
3. `设置 → 通知和状态栏 → 南哪儿课表 → 锁屏课表渠道` → 确认没被关掉
4. 息屏再亮屏一次，或下拉通知栏确认那条通知确实存在

「锁屏显示」分组里那行状态检测就是为这四种情况准备的——它会直接告诉你卡在哪一条。

不需要锁屏通知的话，在「设置 → 锁屏显示」里关掉即可（关掉会立刻撤掉，不留残留）。

    抓到过：`viewingWeek` 初始成 1 导致「本周」永远停在第 1 周

## 十、和鸿蒙版的关系

| | 鸿蒙版 `NJUClassMate/` | 安卓版 `NJUClassMate-Android/` |
| --- | --- | --- |
| 技术栈 | ArkTS + ArkUI + Form Kit | Kotlin + WebView + RemoteViews |
| 抓取脚本 | 4 份 | **同一份，逐字节相同** |
| 算法 | `NextClassEngine.ets` | `Engine.kt`（移植，测试用例一一对应） |
| 锁屏显示 | ✅ Form Kit 锁屏卡片（API 18+） | ✅ 常驻通知 + 自走秒倒计时（本文第三节） |
| 桌面小组件 | ✅ | ✅ |
| 开机自启 | ⚠️ 三方应用受限 | ✅ 官方支持 |
| 安装门槛 | 需要 DevEco + 华为开发者账号 | **自签名即可，零门槛** |

两个工程独立，互不依赖。哪条路能走通就走哪条。
