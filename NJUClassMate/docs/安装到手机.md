# 安装到手机

> 这份文档是给"手上只有工程、还没装任何鸿蒙工具"的情况写的。
> 我为你的机器实际检查过一遍，结论见下面的「第一步：现状」。

---

## 第零步（最重要）：先确认你的手机是哪一版鸿蒙

**这一步决定后面所有事。** 鸿蒙分成两条完全不同的产品线：

| | 兼容版鸿蒙（1.0 ~ 4.x） | 纯血鸿蒙（HarmonyOS NEXT，5.0 及以上） |
| --- | --- | --- |
| 内核 | 鸿蒙微内核 + Linux + AOSP 兼容层 | 纯鸿蒙微内核，无安卓代码 |
| 能装什么 | **APK + HAP** 都行 | **只认 HAP**，APK 装不上 |
| 开发栈 | Java/Kotlin + Android 工具链为主 | ArkTS + ArkUI |
| 对应 API | 最高 API 10 | API 12 起 |
| 本工程能不能装 | ❌ **不能** | ✅ **可以** |

**怎么查**：`设置 → 关于本机 → 版本号`
- 显示 `4.x` 或更低 → 兼容版
- 显示 `5.x` / `6.x` / 带 "NEXT" 字样 → 纯血鸿蒙

### 为什么本工程装不上 HarmonyOS 4

不是没适配，是**能力不存在**：

- 兼容版鸿蒙最高只到 **API 10**，而本工程的最低要求是 **API 12**
- 锁屏卡片是 **API 18** 才有的能力，兼容版鸿蒙全系没有这个能力
- 工程里大量使用 `@kit.*` 模块化导入、`ESObject`、`getUIContext()` 等 API 12 起的写法

### 你这台设备的实际结论（已实测）

2026-09-18 用 `tools/check_phone.py` 实际检查的结果：

```
[2] 手机厂商识别
    ✓ 检测到 华为 Huawei  (VID_12D1)

[3] 手机相关接口明细
    · VID_12D1&PID_107E&MI_00   NOH-AN00 → MTP 文件传输
    · VID_12D1&PID_107E&MI_01   USB Mass Storage Device
    · VID_12D1&PID_107E          USB Composite Device
```

- **型号 NOH-AN00 = 华为 Mate 40 Pro**，麒麟 9000
- **只有 MTP 接口，没有 HDB/ADB 调试接口** → USB 调试还没开
- **官方适配名单已排除 Mate 40 全系**，最高止步鸿蒙 4.2，
  且第三方刷机不可行（麒麟 9000 是 ARM 公版 Cortex-A77/G78 架构，
  缺纯血鸿蒙要求的增强 TrustZone 指令集与安全模块，属于芯片级不兼容）

**所以「升级手机」这条路对你这台机器是死的。**

### 于是你实际只剩两条路

| | 路 B：降级到 API 10 重建 HAP | 路 C：改做安卓 APK |
| --- | --- | --- |
| 能不能装到 Mate 40 Pro | ✅ 能（兼容版鸿蒙支持 APK + HAP） | ✅ 能（同一台机上跑） |
| 桌面小工具 | ✅ 能保留（ArkTS 卡片 API 9 起就有） | ✅ 能（Android App Widget） |
| **锁屏小工具** | ❌ 做不了（HarmonyOS 4 整个系统没有这个能力） | ❌ 做不了（安卓同样没有） |
| 内置浏览器抓课表 | ✅ 保留 | ✅ 保留 |
| 课前提醒 / 周课表 / 考试 / .ics | ✅ 保留 | ✅ 保留 |
| 需要什么工具 | DevEco Studio **4.0（API 10）** + 华为开发者账号 | Android SDK（**免登录可下**）+ JDK，调试签名**可自签** |
| 工作量 | 中：把 `@kit.*` 改回 `@ohos.*`，替换掉 API 12+ 的调用 | 大：等于用 Kotlin 重写一遍，ArkTS 那套全废 |
| 代价 | 要装老版本 DevEco，且仍需华为账号 | 与"鸿蒙原生"的初衷偏离 |

**我的建议**：如果你的核心诉求是"手机上有课表、有桌面小工具、上课前会提醒"，
两条路都能满足，差别只是技术栈。如果更在意"鸿蒙原生"这个属性，走路 B。

无论走哪条，**锁屏小工具都得放弃**——这是平台能力缺失，不是实现问题。

### 路径 A（升级手机）的判定方法

如果你是另一台设备、想确认能不能升级：

`设置 → 关于本机 → 检查更新` / `设置 → 系统和更新 → 软件更新`，
看有没有 HarmonyOS NEXT / 5.x / 6.x 的升级推送，或「升级尝鲜」入口。
- 有推送 → 升级完本工程**开箱即用**，直接走下面第二~五步
- 没有推送 → 说明机型不在适配名单里，走上面两条路之一

## 「能不能直接给我一个装好的安装包？」

**不能。** 这不是偷懒，是一条完整的、缺一环都断的因果链：

```
要一个能装的 .hap
   └─ 必须签名                鸿蒙没有「未知来源安装」，未签名直接拒收
        └─ 必须华为开发者账号   DevEco 的自动签名要登录华为账号
             └─ 必须有 DevEco Studio
                  └─ 编译器（ArkCompiler）、ArkTS 工具链、HarmonyOS SDK 都在它里面
                       └─ 华为下载中心要登录才能拿到直链
```

我实际试过的：

- 全盘扫描 C/D/E → 机器上没有任何鸿蒙工具链
- 访问华为下载中心的 DevEco 页面 → HTTP 200，但页面是 JS 动态渲染的，
  静态 HTML 里**一个下载直链都没有**（下载地址由登录态动态下发）
- 查 npm → `@ohos/hvigor` / `@ohos/hvigor-ohos-plugin` 在公共 npm 源上**不存在**
  （只发布在华为自己的仓库里）
- 官方文档明确写了：「**HarmonyOS SDK 内嵌在 DevEco Studio 中**，无需单独下载和配置」

### 为什么不能"手搓"一个 HAP

HAP 本质是个 zip，我确实能拼出目录结构。但里面最关键的文件是：

```
entry-default.hap
├── ets/modules.abc     ← ArkTS 编译后的字节码，由 ArkCompiler 生成
├── resources.index     ← 资源索引，由 SDK 的 restool 生成
├── module.json         ← 编译后的模块配置
└── ...
```

`modules.abc` 和 `resources.index` **只能由 SDK 里的编译工具产出**。
拼一个空壳出来，装的时候系统校验就过不去；就算强行装进去，一打开就崩。
给你一个装不上的文件，比明确告诉你「现在做不出来」更浪费时间。

### 那什么时候能做出来

装完 DevEco Studio、配好签名之后，**一条命令**就出包：

```bash
bash tools/build_and_install.sh --package-only
```

它会构建并把安装包统一放到 `dist/` 下，文件名带构建模式和日期：

```
dist/nju-classmate-debug-20260918.hap
```

同时打印大小、SHA256 和签名状态。

> ⚠️ 顺带说清一件事：**这个 .hap 拷到手机上是装不上的。**
> 鸿蒙没有"打开文件即安装"这个动作，必须用 hdc 或 DevEco 推到设备上。
> 所以出完包还得跑一次不带 `--package-only` 的安装命令，或者用
> `hdc install -r dist/xxx.hap` 手动推。

### 现在就能拿到的替代物

`dist/nju-classmate-source-YYYYMMDD.zip` —— 整个工程的源码分发包，65 个文件。
用途：备份、发给有 DevEco 的同学让他帮你出包、或者传到云端构建。
**这是源码，不是安装包**，别混淆。

### 为什么不能像安卓那样"直接装"

鸿蒙有一套硬性要求，绕不过去：

1. **HAP 必须签名才能安装。** 没有"未知来源"开关，未签名的包系统直接拒收。
2. **签名需要华为开发者账号。** DevEco 的"自动签名"会登录华为开发者账号，
   自动把连接设备的 UDID 注册进调试证书里。没有账号 → 生成不了可安装的包。
3. **版本必须对得上。** 见上面第零步——HarmonyOS 4 及更早**装不了**本工程。

## 第二步：装 DevEco Studio

1. **下载**：<https://developer.huawei.com/consumer/cn/deveco-studio/>
   选最新的稳定版，**必须 ≥ 5.1.0**（工程里用到了 API 18 的锁屏卡片能力，推荐 6.0.x）。

3. **注册开发者账号**：<https://developer.huawei.com/consumer/cn/>
   免费注册，国内需要实名认证。这一步是硬门槛，跳不过。

4. **首次打开 DevEco**，它会让你下载 SDK，等它跑完。

## 第四步：手机准备

在你的鸿蒙手机上：

1. **开启开发者模式**
   `设置 → 关于本机 → 连续点击「版本号」7 次`

2. **打开 USB 调试**
   `设置 → 系统和更新 → 开发人员选项 → USB 调试`
   （有的机型在 `设置 → 关于本机 → 开发者选项`）

3. **用数据线连电脑**，手机上弹出「是否允许 USB 调试」→ 允许

4. 回到 DevEco，工具栏的设备下拉框里应该能看到你的手机。
   如果没有，装一下华为的 USB 驱动，或者换一根**支持数据传输**的线
   （很多充电线只能供电，这是最常见的坑）。

## 第五步：运行

两种方式，选一个：

### 方式 A：DevEco 里点绿色三角

直接点工具栏的 ▶️ Run。首次会编译 + 签名 + 安装，之后就是增量。

### 方式 B：命令行一键构建并安装

我写了个脚本，它会自己去找 DevEco 自带的工具链：

```bash
bash tools/build_and_install.sh
```

脚本做四件事：
1. 在常见位置搜出 DevEco 自带的 `hvigorw` / `node` / `hdc`
2. 跑 `hvigorw assembleHap` 构建（会自动签名）
3. 用 `hdc list targets` 确认手机连上了
4. `hdc install -r` 安装最新的 HAP

常用参数：

```bash
bash tools/build_and_install.sh --list      # 只看设备和工具链位置，不构建
bash tools/build_and_install.sh --clean     # 先清干净再构建
bash tools/build_and_install.sh --release   # 构建 release 包
```

## 首次使用（装好之后）

1. 打开 App → 「一键导入课表」
2. 选一个入口（本科同学选「本科生教务系统」）
3. 在弹出页面里登录（**如果连的是校园网失败，先连南大 VPN**）
4. 停在「我的课表」页面，等它自动读取
   - 失败会自动重试 4 次
   - 也可以手点「手动读取当前页」
5. 弹出日期选择器 → 选**本学期第一周的任意一天**（会自动归到那一周的周一）
6. **长按桌面空白处 → 卡片（或长按 App 图标 → 卡片）** → 添加「下一节课」「今日课表」
7. **锁屏上双手捏合进入编辑态** → 点卡片位 → 添加「下一节课（锁屏）」

## 常见错误对照表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `hdc list targets` 返回空 | 线只供电 / 没开 USB 调试 / 没装驱动 | 换数据线；确认开发者选项里 USB 调试已开；装华为 USB 驱动 |
| 构建报 `signingConfig "default" not found` | 还没配签名 | 按第三步配置自动签名 |
| 构建报 SDK 版本不满足 | DevEco 版本太低 | 升级到 ≥ 5.1.0 |
| 安装报 `code:9568322 / signature verify failed` | 签名证书里没有这台设备 | 重新「Automatically generate signature」，确保设备已连接 |
| 装上了但打开是白屏 | 首页报错 | DevEco 的 Log 面板过滤 `cn.nju.classmate` 看具体异常 |
| 卡片列表里找不到「南哪儿课表」 | 模块没编译进去 / 设备 API 低于 18 | 锁屏卡片需要 API 18+；桌面卡片 API 12 即可 |
| 导入时页面加载失败 | 不在校园网且未连 VPN | 连南大 VPN 后重试（App 里也有提示） |

## 关于锁屏卡片

- 需要 **API 18+** 的设备（HarmonyOS 5.1 及以上）
- 只在**手机和平板**上支持，2in1/PC 没有锁屏卡片
- 只能用 `1*1` 和 `1*2` 两种尺寸
- 添加路径：**锁屏界面双手捏合 → 进入编辑态 → 点卡片添加位 → 选卡片**

如果编译时报 `renderingMode` 相关的警告或错误，说明你本地 SDK 对它的配置位置有调整，
按 DevEco 的提示改 `entry/src/main/resources/base/profile/form_lock_config.json` 即可
（API 18 的经典写法是把它放在 forms 数组每一项的顶层，我已经这么配了）。

## 装不上时的降级方案

如果一时拿不到华为开发者账号，可以这样先看效果：

1. **用 DevEco 的模拟器**：`Tools → Device Manager → Local Emulator`。
   模拟器也走签名流程，但部分能力（锁屏卡片、2*2 卡片预览）不支持，
   界面和逻辑可以正常验证。
2. **只验证算法**：不用装任何东西，直接跑
   ```bash
   bash tools/run_tests.sh
   ```
   91 项断言覆盖了抓取解析和"下一节课"计算的全部边界，这两块是 App 的核心。
