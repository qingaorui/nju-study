02课表是怎么拿到的

参考 nju.app（南哪课表） 的思路： 不碰接口，只读页面。教务系统挂在统一身份认证后面，自己实现票据流转要处理 加密参数和风控，既脆弱又踩线；让用户在真实浏览器里登录一次、再读已经渲染好的表格， 成本最低、最稳，也最尊重用户的账号安全。

1
点击「一键导入课表」 内置 Web 组件加载统一身份认证登录页
2
用户自己在官方页面登录 应用全程不接触、不存储账号密码，登录完全发生在 nju.edu.cn 域下
3
跳转到「我的课表」，URL 命中目标 onPageEnd 检测到 ehallapp.nju.edu.cn/jwapp/sys/wdkb，自动触发读取
4
注入 rawfile/njubksjw.js 读 #dqxnxqkclb 拿学期名，逐行解析 table tbody tr。 教务系统表格是异步渲染的，所以自带 4 次重试（每次隔 1.2 秒）
5
结果通过 window.njuBridge 回传原生 优先走 javaScriptProxy 注册的桥；桥没收到时退回 runJavaScript 返回值。 两条通道都留，兼容社区脚本
6
归一化并落盘 把 nju.app 语义的 time_count = 末节 − 首节 换算成内部模型的 endSlot，排序后存进 preferences
7
确认开学第一周的周一 算不出周次，卡片就没有意义。第一次导入时弹日期选择器， 无论选哪天都会自动归到那一周的周一
8
刷新卡片 + 重建提醒队列 推给所有已添加的卡片（桌面 + 锁屏），并按新课表重排未来一周的上课提醒

03架构分层

04卡片是怎么"活"起来的

卡片不会自己跳秒。倒计时文字会变旧，状态需要在正确时刻翻转 （"还有 20 分钟" → "正在上课"）。无脑每 5 分钟刷一次既耗电， 还会撞上系统每天 50 次的定时刷新配额。

层次机制作用
基线 updateEnabled + updateDuration: 1 系统每 30 分钟回调一次 onUpdateForm，保证长期不打开也不会僵死
精修 formProvider.setFormNextRefreshTime() 每次刷新后，算准"状态即将变化"的那一刻再预约下一次： 正在上课 → 下课时刷；即将上课 → 上课时刻刷（最短 5 分钟）
事件 onChangeFormVisibility 卡片从不可见变可见时立刻刷一次，用户划过来看到的就是新的
兜底 WorkSchedulerExtensionAbility 每 2 小时后台醒来，重算周次、刷新卡片、重排提醒。 isPersisted: true → 重启后系统自动恢复
前台 30 秒 setInterval 页面上打开时倒计时保持新鲜（纯计算，不碰 IO）
一个必须知道的坑：onAddForm 是同步的

FormExtensionAbility.onAddForm 必须立刻返回数据，不能 await。 所以 WidgetService 特意准备了一个同步版本 buildSync()， 用 preferences.getPreferencesSync / getSync 把课表读出来现算。 这一条如果搞错，表现是"卡片一直是空的、但也不报错"，非常难查。

另一个坑：ArkTS 卡片的数组绑定会静默失败

Record<string, Object> 里混装数组的类型推断很挑，类型对不上时卡片 不报错、只显示空白。「今日课表」卡片因此改用 6 个扁平字符串槽位 （s0Time / s0Name / s0Loc / s0State …）， 一天最多 6 节封顶完全够用。用一点啰嗦换确定性，值得。

05关于「开机自启」——这件必须说清楚的事

⚠️ HarmonyOS NEXT 上，三方普通应用无法监听开机广播自启

StaticSubscriberExtensionAbility 的静态订阅能力主要面向系统应用和企业 MDM 托管应用。 我照样把 BootSubscriber.ets 写好了、module.json5 也配好了—— 但在普通设备上它不会被调用，别指望它。

好消息是：真正让"开机后课表照常工作"并不需要开机自启。 下面三条已经覆盖了全部实际需求，而且它们都是平台原生支持的能力。

① 卡片由系统恢复渲染

重启后桌面重建，卡片提供方被系统拉起。 数据本来就在本机 preferences 里，卡片一渲染就是对的。 这是事实上的"开机自启"。

② 后台任务持久化恢复

WorkScheduler 注册时带 isPersisted: true，任务写进系统，重启后自动恢复， 到点拉起 RefreshWorkAbility 干活。

③ 提醒不依赖应用存活

reminderAgentManager 登记的是系统级提醒， 重启后照样准时弹。这是课表类 App 唯一真正"救命"的功能。

如果还想更激进，可以在 设置 → 应用启动管理 → 南哪儿课表 里 手动打开「允许自启动 / 允许关联启动 / 允许后台活动」。这条引导文案已经写在设置页里。

08已知限制

1. 作息时间是默认值，必须自己核对一次

DEFAULT_TIME_SLOTS 给的是仙林本科常见班次（第 1 节 08:00 起）。 南大各校区、各学期、研究生班次可能不同，夏令时也可能整体挪。 导入后请对着课表核对一次——如果卡片时间整体偏移，问题 99% 出在这里。 设置页提供了「恢复默认作息」。

2. 锁屏卡片的 renderingMode 配置方式在 API 18 之后有调整

当前按经典写法配在 form_lock_config.json 顶层（renderingMode: "autoColor"、 supportDimensions 含 1*2）。编译报错时以本地 SDK 的提示为准核对一次。

3. 抓取依赖教务系统的页面结构

ehall 改版会让 #dqxnxqkclb 或 table tbody 失效。 脚本里加了多级兜底和分阶段的错误提示（findTable / emptyTable / emptyCourses），出问题能快速定位。改版后只需改 njubksjw.js 一个文件，然后跑 test_extractor.js 回归。

4. 登录不自动

统一身份认证必须人工输入，应用不会代填、不会保存密码。代价是重新导入时要登录一次 （Cookie 会保留一段时间）。这是刻意的取舍——不托管用户密码。
